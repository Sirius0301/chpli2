# CHPLI 笔记（Notes N2）切片任务书

> 范围：全文搜索 + 双链/反链（`[[id]]` 稳定 ID）+ 版本历史（保留策略与恢复语义）+ 附件（复用 M3 图片模式）。
> 依据：PROJECT_INSTRUCTIONS「Notes：Markdown、附件、自动保存、搜索、双链、反链和版本历史；链接使用稳定 ID」；N1 任务书裁定的后置项。
> 前置：Notes N1 已交付（2026-11-12）。

---

## 一、需求澄清与切片目标

用户在 N1 编辑器基础上获得四个能力：① 侧栏搜索框按标题/正文/标签全文搜索（与既有两级筛选组合生效）；② 正文 `[[笔记id]]` 双链——编辑器内选择插入、预览中渲染为可点击链接、被引用笔记下方展示反链列表；③ 每次保存自动留存版本，可查看历史并恢复（恢复产生新版本、不破坏历史）；④ 笔记图片附件（对象存储 + 元数据 + 鉴权回源，与 Memo 图片同构）。

## 二、核心决策

记录（2026-11-12）：

- **D1 双链语法与稳定 ID**：语法 `[[<uuid>]]`（N1 已交付的正文中出现 `[[...]]` 本切片起被解析）。编辑器工具栏提供「插入链接」选择器（当前用户笔记列表，排除本篇），插入 UUID 形式的 `[[id]]`——存储层始终是稳定 ID，标题仅作渲染期解析（落实「链接使用稳定 ID」）。无法解析的 `[[...]]`（非 UUID、目标已删除/不可见）渲染为「失效链接」样式，点击无效。
- **D2 反链实现**：`GET /api/notes/{id}/backlinks` → 正文包含字面量 `[[{id}]]` 的笔记（Prisma `body contains`）。反向链接不存储、实时计算——来源可追溯且无冗余数据；被删笔记的反链自动消失（软删除过滤）。
- **D3 全文搜索**：范围 = 标题 + 正文 + 标签；实现 = Postgres `ILIKE`（Prisma `mode: 'insensitive'`）作用于标题/正文 + 标签数组精确 `has`（大小写敏感，文档注明）；查询参数 `q`，与 `tags`/`priorities` 筛选组合（AND 关系）；结果仍按 updatedAt 倒序。数据量级为个人系统，不引入独立搜索引擎（待决策项关闭）。
- **D4 版本历史保留策略**：每次成功更新（含自动保存触发的 PATCH）在同事务写入版本行（完整快照：标题/正文/优先级/标签 + 递增 seq）；**每篇笔记保留最近 50 个版本**，同事务裁剪超出版本；创建即版本 1。
- **D5 恢复语义**：`POST /api/notes/{id}/versions/{seq}/restore` → 事务内：先把当前状态存为新版本（seq+1），再将目标版本内容写回笔记——**恢复即新修订，历史永不改写、无破坏性操作**（符合「重要操作可恢复」底线）；响应为恢复后的 NoteDto，前端刷新编辑器并提示。
- **D6 附件复用 M3 模式**：新表 `note_images`（与 `memo_images` 同构）；存储键 `note-images/{userId}/{noteId}/{imageId}.{ext}`；同一 `ObjectStorageService`（提升至 SharedModule 全局提供，Memo/Notes 共用，module 边界不破）；magic bytes 嗅探、≤5MB、mime 白名单 4 类、客户端 id 幂等、鉴权代理回源、删除先元数据后对象（对象失败 warn 不回滚）——全部沿用 M3 D2–D5 语义。
- **D7 时区/异常/迁移**：迁移仅新建 `note_versions`、`note_images` 两表；版本时间戳为服务端 UTC，前端按用户 locale 渲染；三语文案新增（搜索/反链/历史/附件/失效链接等）。
- **D8 双链安全**：反链与链接解析仅返回当前用户可见笔记（隔离不破）；预览渲染链接仅导航应用内，不产生外跳。

## 三、接口契约（相对 N1 的增量）

- `GET /api/notes?q=`：`q` 可选，与 `tags`/`priorities` 组合（AND）。
- `GET /api/notes/{id}/backlinks` → `NoteSummaryDto[]`（`{id, title}`，按 updatedAt 倒序）。
- `GET /api/notes/{id}/versions` → `NoteVersionDto[]`（`{seq, title, body, priority, tags, createdAt}`，seq 倒序）。
- `POST /api/notes/{id}/versions/{seq}/restore` → 恢复后的 `NoteDto`（D5 语义）。
- `GET/POST /api/notes/{id}/images`、`DELETE /api/notes/{id}/images/{imageId}`、`GET /api/notes/images/{imageId}/file`（同 M3 契约形状）。
- NoteDto 不内嵌版本/附件列表（按需拉取）。

## 四、异常清单（增量）

| # | 场景 | 期望行为 |
|---|---|---|
| E83 | `q` 超长（>128 字符）或 restore 的 seq 不存在 | 400 / 404 `NOTE_VERSION_NOT_FOUND` |
| E84 | 反链目标笔记已软删除 | 不出现在反链中；引用方渲染「失效链接」 |
| E85 | 附件非图片/超大/重复 id | 422（服务层）/ 413 / 幂等返回原记录（M3 E58–E60 同语义） |
| E86 | 他人笔记的搜索/反链/版本/附件 | 404（M0 D5） |
| E87 | 恢复时笔记并发被删 | 404（note 不存在） |
| E88 | 搜索命中他人笔记 | 不可能（userId 条件先行） |

## 五、验收标准

- A76 搜索按标题/正文/标签命中，与筛选组合正确，大小写不敏感（标签除外，已注明）
- A77 编辑器插入 `[[id]]` → 预览渲染为笔记标题链接 → 点击切换到目标笔记；失效链接有样式且不可点
- A78 被引用笔记显示反链列表，点击进入引用方；软删除后反链消失（E84）
- A79 连续编辑产生版本序列；查看历史；恢复旧版本后内容回滚且历史新增一条（非改写）；超过 50 版自动裁剪
- A80 上传图片附件 → 缩略图展示 → 刷新仍在 → 二次确认删除
- A81 跨用户隔离覆盖新端点（E86）；A70–A75 回归通过

## 六、测试覆盖要求

- **集成测试**：搜索（范围/大小写/组合）、反链（含软删）、版本（写入/裁剪/恢复语义/seq 连续性）、附件（复用 M3 用例形状）、隔离。
- **契约测试**：新增路由与 DTO（NoteVersionDto/NoteSummaryDto/NoteImageDto 复用形状）入 OpenAPI，快照更新。
- **组件测试**：搜索防抖联动、双链预处理与渲染（含失效链接）、反链面板、版本面板与恢复按钮、附件组件（复用 M3 组件测试形状）。
- **端到端测试**：搜索→点击命中；插入双链→预览点击导航→反链可见；编辑两次→恢复 v1→内容正确；上传图片→刷新→删除。
